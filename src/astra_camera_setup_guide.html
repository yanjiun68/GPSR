Astra Camera Setup Guide

This guide summarizes the Astra camera setup used in PutrabotUPM-project. It covers device checks, ROS 2 launch commands, expected topics, image preview, and troubleshooting for the RoboCup camera adapter.

1. System Overview

Orbbec Astra USB Camera
        |
        v
astra_camera driver
        |
        +-- /astra/color/image_raw
        +-- /astra/depth/image_raw
        +-- /astra/color/camera_info
        +-- /astra/depth/camera_info
        |
        v
robocup_astra_camera_node.py
        |
        +-- /camera/image_raw
        +-- /camera/depth/image_raw
        +-- /camera/camera_info
        +-- /camera/depth/camera_info
        +-- /diagnostics

The Astra driver publishes native topics under /astra. The RoboCup adapter node republishes the camera feed under stable task-facing topics beginning with /camera.

2. Hardware Connection Check

Connect the Astra camera by USB, then check whether Linux sees it:

lsusb | grep -i -E "orbbec|astra|2bc5"

Expected device pattern:

2bc5:0401 Orbbec Astra

Use the Astra driver device listing tool after sourcing the workspace:

source /opt/ros/humble/setup.bash
source install/setup.bash
ros2 run astra_camera list_devices_node

Expected result from the local test:

Device name: Astra
URI: 2bc5/0401@...
Serial number: 18022710375

3. Build Workspace

source /opt/ros/humble/setup.bash
colcon build --packages-select astra_camera my_robot_nav
source install/setup.bash
If you recently added or changed launch files or Python nodes, rebuild and source install/setup.bash again before launching.

4. Launch Native Astra Driver

The project does not contain a file literally named astra.launch.py. The relevant native launch file is:

astra_camera astra_mini.launch.py

Run it directly:

source /opt/ros/humble/setup.bash
source install/setup.bash
export RMW_IMPLEMENTATION=rmw_fastrtps_cpp
ros2 launch astra_camera astra_mini.launch.py namespace:=astra

Expected native topics:

/astra/color/image_raw
/astra/color/camera_info
/astra/depth/image_raw
/astra/depth/camera_info
/astra/ir/image_raw
/astra/points

5. Launch RoboCup Astra Adapter

Use the package-local launch file added for RoboCup tasks:

source /opt/ros/humble/setup.bash
source install/setup.bash
export RMW_IMPLEMENTATION=rmw_fastrtps_cpp
ros2 launch vision astra_camera.launch.py

This launch starts:

Component Purpose
astra_camera/astra_mini.launch.py Starts the Astra RGB-D hardware driver.
robocup_astra_camera_node.py Relays Astra topics into stable RoboCup camera topics.

6. Expected RoboCup Topics

Topic Message Type Purpose
/camera/image_raw sensor_msgs/msg/Image RGB image feed for perception.
/camera/depth/image_raw sensor_msgs/msg/Image Depth image feed for distance estimation.
/camera/camera_info sensor_msgs/msg/CameraInfo RGB camera intrinsics.
/camera/depth/camera_info sensor_msgs/msg/CameraInfo Depth camera intrinsics.
/diagnostics diagnostic_msgs/msg/DiagnosticArray Adapter health and frame counters.

7. Verify Nodes and Topics

source install/setup.bash
export RMW_IMPLEMENTATION=rmw_fastrtps_cpp
ros2 node list
ros2 topic list
ros2 topic info /camera/image_raw -v
ros2 topic info /camera/depth/image_raw -v

Check whether images are being published:

ros2 topic hz /camera/image_raw
ros2 topic hz /camera/depth/image_raw

8. Preview Raw Image Feed

Use rqt_image_view if a GUI display is available:

source install/setup.bash
export RMW_IMPLEMENTATION=rmw_fastrtps_cpp
rqt_image_view /camera/image_raw

You can also preview the native Astra feed directly:

rqt_image_view /astra/color/image_raw
In the local hardware test, the Astra driver started RGB and depth streams at 640x480 at 30 Hz and advertised /astra/color/image_raw and /astra/depth/image_raw.

9. Troubleshooting Flow

Camera not working
        |
        +-- lsusb does not show Orbbec/Astra
        |       |
        |       v
        |   Replug USB, try another port, check cable/power
        |
        +-- list_devices_node shows no camera
        |       |
        |       v
        |   Check udev permissions and astra_camera install
        |
        +-- launch says Resource busy
        |       |
        |       v
        |   Stop other camera processes or replug camera
        |
        +-- topics exist but ros2 topic list hangs
        |       |
        |       v
        |   Use Fast DDS: export RMW_IMPLEMENTATION=rmw_fastrtps_cpp
        |
        +-- topics exist but no image in rqt
                |
                v
            Check DISPLAY, QoS, topic name, and driver logs

10. Common Issues

Symptom Likely Cause Fix
Resource busy Another process still owns the Astra USB device. Close previous launch/rqt processes, then unplug and replug the camera if needed.
Lifecycle or ROS graph commands keep waiting DDS discovery issue, observed with CycloneDDS in this workspace. Run with export RMW_IMPLEMENTATION=rmw_fastrtps_cpp.
No image in viewer Wrong topic, no GUI display, or camera stream not active. Check ros2 topic list, ros2 topic hz, and driver logs.
No camera listed USB, permission, or driver issue. Check lsusb, udev rules, and list_devices_node.

11. Recommended RoboCup Startup Sequence

1. Connect Astra camera by USB.
2. Confirm Linux sees the device with lsusb.
3. Source ROS and workspace setup files.
4. Export Fast DDS RMW implementation.
5. Launch astra_camera.launch.py from the vision package.
6. Verify /camera/image_raw and /camera/depth/image_raw.
7. Start GPSR/perception nodes that consume /camera topics.

12. Quick Command Reference

# Build
source /opt/ros/humble/setup.bash
colcon build --packages-select astra_camera my_robot_nav
source install/setup.bash

# Detect camera
lsusb | grep -i -E "orbbec|astra|2bc5"
ros2 run astra_camera list_devices_node

# Launch RoboCup camera adapter
export RMW_IMPLEMENTATION=rmw_fastrtps_cpp
ros2 launch vision astra_camera.launch.py

# Inspect topics
ros2 topic list
ros2 topic hz /camera/image_raw
ros2 topic hz /camera/depth/image_raw

# Preview RGB image
rqt_image_view /camera/image_raw
The adapter standardizes topic names but does not fix a hardware-level Resource busy error. If the Astra driver cannot open the USB device, stop competing processes or replug the camera.
